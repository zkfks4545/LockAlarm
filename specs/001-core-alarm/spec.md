# 기능 명세: 개인용 루틴 알람 핵심 경험

**Feature Branch**: `001-core-alarm`  
**Created**: 2026-08-01  
**Status**: 0.15.13 keeps new-alarm-first overlap preemption and one-way device media-volume recovery, makes home-toggle activation today-first even for stale automatically calculated dates, preserves explicit future dates, separates the upward swipe area from the bottom action row, and retains the separate daily repeat option; scheduling and session recovery remain in scope; real-device behavior is still open
**Input**: 지정 시각에 기기 상태를 초기화하고 로컬 콘텐츠 또는 YouTube 임베디드 플레이어를 실행하는 개인용 Android 알람

## 제품 의도

사용자는 잠들기 전 또는 집중 루틴을 시작하기 전에 알람을 예약한다. 예약 시각이 되면 앱은 잠금 상태에서도 놓치기 어려운 화면과 소리를 제공하고, 사용자가 지정한 밝기와 미디어 음량을 시작값으로 한 번 적용한다. 알람 중 사용자는 기기 값을 자유롭게 바꿀 수 있으며, 해제 시에는 선택한 정책에 따라 시작 전 상태로 돌아가거나 현재 상태를 유지한다.

이 명세는 현재 프로토타입 코드보다 우선하는 Living Spec이다. 기존 코드는 요구사항을 검증하는 출발점이며, 명세와 충돌할 경우 계획 단계에서 수정 또는 제거 대상을 결정한다.

## Clarifications

### Session 2026-08-01

- **Q**: 첫 정식 범위에서 알람 개수와 반복 규칙을 어디까지 지원하는가? **A**: 복수 알람과 `ONE_TIME`, 선택 요일 `WEEKLY`, 모든 요일을 대상으로 하는 `DAILY`, 명시적 포함·제외 날짜를 지원한다. 제외 날짜가 우선하고 동일 날짜·시각은 한 발생으로 중복 제거한다.
- **Q**: 스누즈는 어떤 규칙으로 동작하는가? **A**: 울림과 각 스누즈 재울림에서 횟수 제한 없이 고정 5분 스누즈를 제공한다. 각 예약은 회차와 예정 시각을 검증하며, 스누즈는 같은 세션을 유지하므로 기기 상태를 복원하거나 초기값을 다시 적용하지 않고 최종 해제 때만 복원 정책을 적용한다.
- **Q**: 개인용 서비스에서 무엇을 저장하는가? **A**: 계정·서버·클라우드 동기화 없이 알람 정의와 최근 사용 콘텐츠만 앱 전용 로컬 데이터베이스에 저장한다. 실행·스누즈·해제·오류 행동 로그는 저장하지 않는다. 로컬 파일은 열람 전용이며 YouTube 항목만 URL 복사를 제공한다.
- **Q**: 다른 알람이 현재 울림 또는 스누즈와 겹치면 어떻게 조정하는가? **A**: 새 정규 발생이 항상 우선한다. 현재 울림, 스누즈 대기, 스누즈 재울림 중인 기존 발생은 `PREEMPTED`로 종결하고 새 알람을 즉시 시작한다. 단일 포그라운드 서비스·재생 세션만 유지하므로 두 알람을 동시에 섞어 재생하지 않는다. Room 트랜잭션이 활성 발생을 먼저 선점하고 서비스는 해당 새 occurrence가 아직 `CLAIMED`인지 확인한 뒤 기존 화면·재생·스냅샷을 정리한다. 이전 FIFO 정책의 `WAITING` 행은 다시 시작하지 않고 취소한다.
- **Q**: 로컬 영상과 소리는 어떻게 조합하는가? **A**: 별도 로컬 음악 파일이 있으면 그 음악을 사용하고, 없으면 영상 자체 오디오를 사용한다. 영상 오디오가 없거나 재생에 실패하면 기기 기본 알람음으로 자동 대체한다.
- **Q**: YouTube는 외부 앱으로 이관되는가? **A**: 아니다. 정확 알람이 전달되면 세션 생성과 기기 초기값 적용 직후 공식 IFrame API 플레이어를 알람 전체화면 안에서 재생한다. 다운로드·추출·광고 차단은 하지 않는다.
- **Q**: 홈 카드 미리보기는 알람 활성화와 같은 설정인가? **A**: 아니다. 각 알람의 미리보기 스위치는 Room에 별도로 저장되며 스케줄 revision·예약·울림 동작을 변경하지 않는다. 로컬 미디어는 홈 카드에서 음소거 재생하고 YouTube는 공식 썸네일만 표시한다. YouTube 공식 IFrame 플레이어는 실제 알람 울림 화면에서만 사용한다.
- **Q**: 홈 알람 목록은 활성 알람을 먼저 보여주는가? **A**: 아니다. 활성 여부와 무관하게 사용자가 설정한 현지 시각(`localTimeMinutes`) 오름차순, 같은 시각은 알람 ID 오름차순으로 정렬한다.
- **Q**: 스톱워치와 함께 제공하는 타이머는 어떻게 동작하는가? **A**: 타이머 탭에서 초 단위 시간을 입력하고 시작·일시정지·계속·초기화를 사용할 수 있다. 남은 시간은 `SystemClock.elapsedRealtime()`으로 계산해 화면 이동 뒤에도 유지한다.

### Session 2026-08-16 — 0.15.2 알람 음량 점진 상승

- 로컬 음악, 오디오 트랙이 있는 로컬 영상, 기기 기본 알람 URI는 기존 `MediaPlayer` 경로를 유지하면서 개별 gain을 기본 10%에서 시작해 30초 동안 250ms 간격으로 100%까지 올린다.
- 램프는 `MediaPlayer.setVolume`만 사용한다. 알람 시작 순간 `DeviceStateController`가 적용한 기기 `STREAM_MUSIC` 초기값은 실행 중 다시 설정하지 않는다.
- 재생 객체·세션 ID·generation이 현재 세션과 일치할 때만 램프 콜백을 적용하고, 최종 해제·스누즈·선점·서비스 종료 전에 콜백을 제거한다. `ToneGenerator` 대체음은 고정 음량으로 유지한다.

### Session 2026-08-16 — 0.15.3 내비게이션·편집 뒤로가기 보정

- 좁은 화면 하단 내비게이션의 세 항목을 동일 가중치로 배치하고 시스템 내비게이션 인셋을 적용해 타이머 탭이 잘리지 않게 한다.
- 넓은 화면 레일과 본문에 Scaffold 인셋을 적용해 하단 시스템 영역과 겹치지 않게 한다.
- 알람 편집 화면의 시스템 뒤로가기는 상단 뒤로 버튼과 동일하게 편집 화면을 닫는다.

- Android 애플리케이션 표시 이름을 `LockAlarm`으로 사용한다. 패키지 식별자와 알람 채널 동작은 변경하지 않는다.

### Session 2026-08-17 — 0.15.5 알람 종료 버튼 스타일 통일

- 실제 알람 종료 버튼은 5분 스누즈와 같은 반투명 둥근 버튼으로 표시하고 문구는 `알람끄기`로 사용한다.
- 타이머 완료 전 비활성·세션 검증·서비스 해제 경로는 기존 정책을 유지한다.

### Session 2026-08-17 — 0.15.6 화면 크기 변경 시 영상 위치 보존

- 폴드 접기·펼치기와 넓은 화면·좁은 화면 전환 중 표면이 잠시 반환하는 0초 위치는 유효한 재생 위치로 저장하지 않는다.
- 마지막 정상 로컬 영상 위치를 같은 `sessionId`의 표면 인계 상태로 유지하고, 음원 서비스·타이머·기기 상태 세션은 재시작하지 않는다.

### Session 2026-08-24 — 0.15.7 화면 잠금 타이머 켜짐/꺼짐

- 알람별 화면 잠금 타이머를 켜거나 끌 수 있다. 켜짐 상태 지연은 0~60초이며, 꺼짐 상태는 0초로 저장한다.
- 0초에서는 울림 시작 시점부터 종료·스누즈·위로 밀기 조작을 허용하고, 기존 세션·기기 상태 정책은 유지한다.

### Session 2026-09-03 — 0.15.8 새 알람 우선 및 음량 복원

- 현재 `CLAIMED`, `FIRING`, `SNOOZED`, `SNOOZE_CLAIMED` 발생이 있더라도 새 정규 발생을 Room 트랜잭션에서 우선 선점하고 기존 발생은 `PREEMPTED`로 종결한다. 새 발생은 `WAITING`으로 저장하지 않는다.
- 서비스는 새 발생의 occurrence·session 식별자와 `CLAIMED` 상태를 재확인한 뒤 이전 세션을 정리하므로, 더 오래된 start intent가 새 세션을 역으로 종료할 수 없다.
- 알람 시작 시 지정한 `STREAM_MUSIC` 목표보다 현재 기기 음량이 낮아지면 울림 중 2초 간격으로 최대 음량의 5%(최소 1단계)씩 목표까지 올린다. 목표보다 높은 값은 낮추지 않는다. 스누즈 대기·선점·해제·취소·서비스 종료에서는 감시를 멈추고, 같은 세션의 스누즈 재울림에서만 다시 시작한다.
- 기존 MediaPlayer 개별 gain 상승과 시작 시 밝기·음량 초기값 1회 적용, 최종 복원 정책은 유지한다.

### Session 2026-09-03 — 0.15.9 시간 입력 날짜 보정

- 새 알람은 오늘 날짜로 시작하며, 숫자 시·분을 입력하는 중간 값으로 날짜를 자동 변경하지 않는다.
- 저장 시점에 오늘의 선택 시각이 현재 시각보다 과거일 때만 날짜를 내일로 보정한다. 아직 지나지 않은 시각은 오늘 날짜로 유지한다.

### Session 2026-09-03 — 0.15.10 알람 편집 화면 테마 동기화

- 홈에서 저장한 다크·라이트 테마 상태를 앱의 공통 `RoutineAlarmTheme`이 알람 목록과 알람 추가·편집 화면에 동일하게 전달한다.
- 알람 편집 화면의 루트 표면은 현재 `MaterialTheme.colorScheme.background`를 직접 그려 테마 배경과 입력·카드 색상 계층이 일치하도록 한다.
- 테마 저장·시스템 바 색상·알람 편집 동작과 알람 세션 동작은 변경하지 않는다.

### Session 2026-09-04 — 0.15.11 알람 활성화 날짜 우선 및 매일 반복

- 알람을 새로 만드는 기본값은 유지하고, 저장된 알람을 활성화하는 순간의 예약 날짜만 오늘 우선으로 다시 계산한다. 사용자 날짜 선택 표식이 없는 `ONE_TIME`은 오늘의 설정 시각이 아직 남았으면 오늘, 이미 지났으면 내일로 예약한다.
- 편집 화면에서 `오늘`, `내일` 또는 날짜 선택을 직접 누른 `ONE_TIME`은 명시 날짜를 유지하되, 그 날짜·시각이 지나면 다음날로 보정한다.
- 반복 방식에 선택 요일 `WEEKLY`와 별도의 모든 요일 `DAILY`를 제공한다. `DAILY`도 포함·제외 날짜를 적용하며 제외 날짜가 우선한다.

### Session 2026-09-04 — 0.15.12 홈 활성화 재기준 및 종료 버튼 터치

- 홈 알람 카드의 `알람` 토글로 비활성 알람을 켜는 것도 편집 화면의 활성화와 동일하게 `prepareForActivation`을 거친다. 날짜 선택 표식이 없거나 이전 자동 계산으로 남은 과거·미래 날짜는 오늘의 설정 시각이 남아 있으면 오늘로 재기준하고, 이미 지난 경우에만 내일로 예약한다.
- 사용자가 직접 선택한 미래 날짜는 유지한다. 사용자가 고른 날짜가 과거이면 오늘 시각이 남아 있을 때 오늘로 재기준하고, 오늘 시각이 지난 경우 내일로 보정한다. 레거시 SharedPreferences 가져오기는 날짜 선택 표식을 남기지 않는다.
- 공통 울림 표면의 중앙 `AlarmDismissGestureView`는 명시적인 `5분 스누즈`·`알람끄기` 버튼보다 먼저 추가해 FrameLayout의 역순 터치 전달에서 버튼이 제스처 영역에 가로채이지 않게 한다.

### Session 2026-09-04 — 0.15.13 울림 화면 동작 행 배치

- 공통 울림 표면의 `AlarmDismissGestureView`는 하단 명시 동작 행보다 위쪽의 독립된 영역을 사용하며, 행과 충분한 세로 간격을 둔다.
- `5분 스누즈`와 `알람끄기`는 전체 폭 부모 안에서 중앙에 인접한 하나의 가로 행으로 배치한다. 최초 울림에서는 스누즈가 왼쪽, 종료가 오른쪽이고, 스누즈 후에는 종료만 중앙에 표시한다.
- 버튼 행은 타이머 잠금 상태와 서비스 세션 검증을 그대로 사용하며, 잠금화면 Activity와 홈 복구 오버레이는 동일한 표면 배치를 사용한다.

### Session 2026-09-11 — 0.15.14 스누즈 재생 초기화·미리보기 경계

- 스누즈 예약이 성공하면 이전 로컬 영상·YouTube 표면의 재생 위치 소유권을 무효화한다. 재울림은 영상과 음원을 모두 0초에서 시작하며, 일반 화면 복구·회전·표면 교체의 같은 세션 이어재생은 유지한다.
- 홈·편집 로컬 영상 미리보기는 카드 크기의 `TextureView`와 음소거 `MediaPlayer`를 사용하고, 중앙 크롭은 텍스처 변환으로 적용해 인접 카드로 출력 표면이 번지지 않게 한다.
- 이 버전에서는 스누즈 횟수 제한 및 스누즈 회차·예정 시각 검증 정책을 변경하지 않는다.

### Session 2026-09-11 — 0.15.15 스누즈 전달 검증

- 스누즈 예약 인텐트는 `alarmId`, `occurrenceId`, `scheduleRevision`, `sessionId`, `snoozeCount`, `dueAtMillis`를 함께 전달한다.
- Broadcast 수신부와 포그라운드 재생 서비스는 현재 `SNOOZED` 세션의 모든 식별자와 회차·예정 시각을 각각 확인한 뒤 Room 선점과 재생 재개를 허용한다. 재생 중인 동일 회차의 중복 서비스 시작은 현재 세션과 일치할 때만 멱등 처리한다.
- 같은 부팅에서 저장된 elapsed realtime 기한이 우선이며, 재부팅·부팅 카운터 미확인·elapsed 기한 누락 시 wall-clock 예정 시각으로 보조한다. 벽시계 변경으로 예약이 조기 전달되면 현재 예약을 버리지 않고 남은 시간으로 다시 등록한다.
- 0.15.15에서도 스누즈 횟수는 기존 1회로 유지한다. 무제한 전환은 이 검증 결과를 바탕으로 별도 정책 변경에서 다룬다.

### Session 2026-09-11 — 0.15.16 무제한 스누즈 및 확인 알림

- `FIRING → SNOOZED → FIRING` 전이는 현재 `snoozeCount` 값과 무관하게 허용하며, 각 재울림 화면과 진행 중 알림에 스누즈 액션을 계속 표시한다.
- 스누즈 예약이 성공하면 기존의 대기 상태 알림과 별도로 `스누즈 설정 완료` 알림을 보내고 `5분 뒤에 알람이 울립니다.`를 표시한다. 재울림 시작·최종 해제·취소·선점 시 확인 알림은 정리한다.
- 회차·예정 시각 검증과 같은 부팅 elapsed/reboot wall-clock fallback은 유지한다.

### Session 2026-09-11 — 0.15.17 YouTube 영상 조작 차단

- YouTube 공식 IFrame 플레이어는 컨트롤·키보드·전체화면 옵션을 끄고 자동 재생되는 표시 전용 표면으로 유지한다.
- WebView의 터치·롱프레스·포인터·키 입력은 소비해 영상 탭, 스와이프, 탐색, 일시정지, 링크 이동을 막으며 알람 native 스누즈·알람끄기 동작은 유지한다.

### Session 2026-09-19 — 0.15.18 해제 시 밝기 복원 보완

- 알람 시작 전 밝기를 복원한 뒤 자동/수동 밝기 모드를 되돌려 자동 밝기 기기에서 이전 밝기가 즉시 반영되도록 한다.
- 서비스 종료가 최종 해제·취소와 겹칠 때 Room 발생 상태가 이미 종료된 경우에만 저장된 기기 상태를 재복원한다. `FIRING` 발생은 여전히 프로세스 복구를 위해 유지한다.
- 알람별 `RESTORE_PREVIOUS`와 `KEEP_CURRENT` 정책은 유지하며, 사용자가 울림 중 변경한 밝기는 최종 정책에 따라 복원하거나 유지한다.

### Session 2026-09-19 — 0.15.19 미디어 길이 기반 화면 잠금 타이머

- 화면 잠금 타이머가 켜져 있으면 지연을 0초부터 선택한 로컬 음원·영상·애니메이션 이미지 중 가장 긴 미디어 길이까지 설정할 수 있다.
- YouTube 또는 기본 알람처럼 로컬 메타데이터로 재생 길이를 확인할 수 없는 콘텐츠는 60초를 최대값으로 사용한다.
- 편집 화면과 울림 서비스는 동일한 유효 최대값으로 저장·해제·스누즈 판정을 제한한다.

### Session 2026-09-23 — 0.15.20 반복 알람 날짜 우선 및 해제 후 재예약

- 매일·요일 반복 알람의 복구 예약은 저장된 `triggerAtMillis`가 미래라는 이유만으로 유지하지 않고 현재 현지 날짜의 다음 유효 발생을 다시 계산한다. 오늘의 설정 시각이 남아 있으면 오늘을 우선하며, 명시적 미래 `ONE_TIME` 날짜는 이 규칙으로 덮어쓰지 않는다.
- 반복 알람의 최종 해제는 오늘 발생을 처리한 것으로 간주한다. 해제 시점이 설정 시각보다 이르더라도 오늘의 설정 시각을 기준으로 다음 유효 발생을 계산해 매일 알람은 내일부터 다시 울리게 한다.
- 일반 전달 직후 예약과 해제 시 재확인을 모두 유지해, 전달·복구·서비스 종료 순서가 달라져도 같은 날의 반복 알람이 다시 살아나지 않게 한다.

### Session 2026-08-13 — 0.12.0 잠금화면형 울림 표면

- 잠금화면 `AlarmRingActivity`와 잠금 해제 후 홈 복구 `TYPE_APPLICATION_OVERLAY`는 하나의 `AlarmOverlayController`가 만든 동일한 울림 표면을 사용한다.
- 로컬 영상·이미지 또는 공식 YouTube 플레이어는 전체 화면 배경으로 유지한다. 상단 중앙에는 현재 현지 시각 `HH:mm`을 크게 표시하고 바로 아래에 알람 이름을 표시하며, 시계는 매분 갱신한다. 시스템 상태바를 모사하는 별도 UI는 추가하지 않는다.
- 우측 상단 `CircularDismissView`는 타이머 진행률과 남은 초를 표시하고 완료 시 100% 진행률과 완료 표시를 유지하는 전용 표시기다. 타이머 전후 모두 종료 입력을 받지 않는다.
- 타이머 완료 전에는 종료·위 스와이프·스누즈·YouTube/로컬 미디어 조작을 모두 차단하고, 하단 중앙에는 잠금 안내와 남은 시간을 표시하는 비활성 손잡이를 둔다.
- 타이머 완료 뒤 하단 중앙 가로 행의 5분 스누즈와 알람끄기 버튼을 활성화한다. 스누즈는 현재 울림 회차마다 횟수 제한 없이 가능하며, 동작 행 위쪽의 `AlarmDismissGestureView`는 수직 위 이동이 160dp 이상일 때만 종료 요청을 보낸다. 짧거나 수평 우세 드래그는 거부한다.
- X와 위 스와이프는 `AlarmPlaybackService.dismissIntent(context, alarm.id, session.sessionId)`로 요청한다. 서비스는 기존 session/time 검증을 유지하고, 화면 복구·회전·Activity/오버레이 전환은 세션 또는 `ringStartedAtMillis`를 새로 만들지 않는다.

## 사용자 시나리오 및 테스트

### 사용자 스토리 1 - 놓치지 않는 기본 알람 (Priority: P1)

사용자는 미래 시각을 선택해 알람을 예약하고, 화면이 잠겨 있거나 앱을 떠난 상태에서도 해당 시각에 알람 화면과 소리를 받으며, 안내된 지연 시간이 지나면 직접 해제한다.

**Why this priority**: 지정 시각에 울리고 해제할 수 없다면 다른 개인화 기능은 가치가 없다.

**Independent Test**: 지원 기기에서 사용자가 입력한 초 간격으로 테스트 알람을 예약하고 화면을 잠근 뒤, 전체화면 진입·소리 재생·원형 지연 표시와 X 해제를 한 흐름으로 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 필수 접근이 허용되고 미래 시각이 선택됨, **When** 사용자가 알람을 저장함, **Then** 앱은 예약 성공과 다음 실행 시각을 명확히 표시한다.
2. **Given** 활성 알람의 시각에 기기가 잠겨 있음, **When** 시스템이 알람을 전달함, **Then** 잠금 화면 위에 알람 경험이 표시되고 로컬 알람음이 시작된다.
3. **Given** 알람이 활성 상태이고 해제 지연이 지나지 않음, **When** 사용자가 화면을 봄, **Then** 우측 상단 원형 진행과 남은 시간이 보이고 종료 동작은 사용할 수 없다.
4. **Given** 해제 지연이 지남, **When** 원형 표시가 X로 바뀌고 사용자가 이를 누름, **Then** 재생과 활성 알람 알림이 종료되고 같은 알람이 다시 울리지 않는다.
5. **Given** 알람이 활성 상태임, **When** 사용자가 홈 화면으로 이동함, **Then** 로컬 알람음은 해제 전까지 계속 재생되고 알림에서 알람 화면 또는 해제 동작에 접근할 수 있다.

### 사용자 스토리 2 - 복수 일정과 날짜 예외 (Priority: P1)

사용자는 여러 알람을 저장하고, 각 알람을 한 번만 실행하거나 선택한 요일 또는 매일 반복하며, 특정 날짜를 추가하거나 제외할 수 있다.

**Why this priority**: 사용자가 선택한 D 범위의 핵심이며, 다음 실제 실행을 예측하고 신뢰하려면 콘텐츠 기능보다 먼저 일정 모델이 안정되어야 한다.

**Independent Test**: 서로 다른 세 알람에 1회성, 월·수·금 요일별 반복, 매일 반복과 포함·제외 날짜를 지정하고 다음 실행 계산과 독립 취소를 검증한다.

**Acceptance Scenarios**:

1. **Given** 서로 다른 활성 알람 여러 개가 저장됨, **When** 앱을 다시 열거나 기기를 재부팅함, **Then** 각 알람의 다음 실행 시각이 독립적으로 유지·재등록된다.
2. **Given** 월·수·금 07:00 반복 알람, **When** 다음 실행을 계산함, **Then** 현재 이후 가장 이른 유효 요일의 현지 시각 07:00을 선택한다.
3. **Given** 다음 반복 날짜가 제외 목록에 있음, **When** 다음 실행을 계산함, **Then** 해당 날짜를 건너뛰고 다음 유효 날짜를 선택한다.
4. **Given** 기본 요일이 아닌 미래 날짜가 포함 목록에 있음, **When** 해당 날짜가 가장 이른 후보임, **Then** 같은 알람 시각으로 한 번 실행한다.
5. **Given** 기본 요일과 포함 날짜가 같은 발생을 가리킴, **When** 예약을 계산함, **Then** 같은 날짜·시각에는 한 번만 실행한다.
6. **Given** 한 알람을 비활성화하거나 삭제함, **When** 예약 변경이 완료됨, **Then** 다른 알람의 저장 상태와 시스템 예약은 바뀌지 않는다.

### 사용자 스토리 3 - 5분 뒤 다시 알림 (Priority: P1)

사용자는 알람을 완전히 끝내지 않고 원하는 만큼 미뤄 매번 정확히 5분 뒤 같은 알람을 다시 받을 수 있다.

**Why this priority**: 사용자가 이번 범위에 명시적으로 추가한 핵심 조작이며, 예약·세션·복원 정책을 함께 검증한다.

**Independent Test**: 최초 울림과 두 번 이상의 재울림에서 스누즈를 반복하고, 각 대기 알림·별도 확인 알림·5분 뒤 재울림·최종 해제를 한 흐름으로 검증한다.

**Acceptance Scenarios**:

1. **Given** 현재 울림 회차가 진행 중임, **When** 사용자가 스누즈를 누름, **Then** 1초 이내 재생과 전체화면이 멈추고 누른 시점부터 5분 뒤 다음 회차 하나가 예약되며 `5분 뒤에 알람이 울립니다.` 별도 알림이 표시된다.
2. **Given** 스누즈 대기 중임, **When** 사용자가 밝기 또는 음량을 바꿈, **Then** 앱은 값을 복원하거나 다시 지정값으로 덮어쓰지 않는다.
3. **Given** 5분이 지남, **When** 같은 세션이 다시 울림, **Then** 시작 전 스냅샷 저장과 초기 밝기·음량 적용을 반복하지 않고 콘텐츠와 음원만 재개한다.
4. **Given** 이미 한 번 이상 스누즈함, **When** 재울림 화면이 표시됨, **Then** 스누즈 버튼이 다시 제공되고 사용자는 계속 5분 뒤 재울림을 예약할 수 있다.
5. **Given** 스누즈 대기 중임, **When** 사용자가 대기 알림에서 최종 해제함, **Then** 재울림은 취소되고 복원 정책이 한 번 적용되며 반복 알람의 다음 정규 일정은 유지된다.
6. **Given** 동일 스누즈 동작 또는 시스템 전달이 중복됨, **When** 앱이 처리함, **Then** 재울림 예약과 활성 재생은 각각 하나만 존재한다.

### 사용자 스토리 4 - 기기 상태를 루틴 시작값으로 적용 (Priority: P2)

사용자는 알람별 밝기와 미디어 음량 시작값을 지정하고, 해제 후 시작 전 값을 복원할지 현재 값을 유지할지 선택한다.

**Why this priority**: 일반 알람과 구분되는 핵심 루틴 기능이며, 사용자가 원하는 강도의 콘텐츠 경험을 만든다.

**Independent Test**: 시작 전 밝기·음량과 다른 값을 저장한 뒤 알람을 실행하고, 실행 중 값을 수동 변경한 다음 두 복원 정책을 각각 검증한다.

**Acceptance Scenarios**:

1. **Given** 밝기 80%와 미디어 음량 70%가 설정됨, **When** 알람이 시작됨, **Then** 두 값은 시작 시점에 한 번 적용된다.
2. **Given** 활성 알람 중 사용자가 밝기를 바꾸거나 미디어 음량을 목표보다 높게 바꿈, **When** 알람이 계속됨, **Then** 앱은 그 값을 다시 설정값으로 덮어쓰지 않는다. 미디어 음량을 목표보다 낮추면 앱은 제한된 속도로 목표까지 회복한다.
3. **Given** `시작 전 값 복원`이 선택됨, **When** 알람이 해제됨, **Then** 저장된 시작 전 밝기 상태와 미디어 음량이 복원된다.
4. **Given** `현재 값 유지`가 선택됨, **When** 알람이 해제됨, **Then** 해제 시점의 밝기와 미디어 음량을 변경하지 않는다.

### 사용자 스토리 5 - 로컬 시각 콘텐츠로 개인화 (Priority: P3)

사용자는 기기의 이미지, GIF 또는 영상을 알람 화면으로 선택하고, 영상 자체 소리·별도 로컬 음악·기기 기본 알람음 중 재생 소스를 선택한다.

**Why this priority**: 외부 네트워크 없이도 개인화된 알람 경험을 제공한다.

**Independent Test**: 각 지원 파일 형식을 하나씩 선택한 뒤 앱을 재시작하고 알람을 실행하여 접근 유지, 렌더링, 무음 반복과 별도 음원 재생을 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 지원 형식의 파일이 선택됨, **When** 앱이 종료 후 다시 열림, **Then** 선택 상태와 읽기 접근이 유지된다.
2. **Given** 이미지 또는 GIF가 지정됨, **When** 알람이 시작됨, **Then** 콘텐츠가 화면 영역에 맞춰 표시되고 GIF는 애니메이션된다.
3. **Given** 오디오 트랙이 있는 영상과 `영상 소리`가 지정됨, **When** 알람이 시작됨, **Then** 영상은 반복 표시되고 같은 파일의 오디오가 미디어 음량으로 반복 재생된다.
4. **Given** 이미지·GIF·무음 영상이 지정됨, **When** 사용자가 별도 로컬 음악을 선택함, **Then** 해당 음악이 포그라운드 서비스에서 반복 재생된다.
5. **Given** 파일이 삭제되거나 접근 권한이 사라짐, **When** 알람이 시작됨, **Then** 앱은 기본 시각 화면과 기기 기본 알람음으로 안전하게 대체한다.

---

### 사용자 스토리 6 - YouTube 앱 내부 임베디드 재생 (Priority: P4)

사용자는 YouTube URL을 지정하고 알람 시작 시 공식 IFrame API 플레이어로 앱의 알람 화면 안에서 콘텐츠를 재생한다.

**Why this priority**: 원하는 온라인 콘텐츠를 알람 화면 안에서 사용하되 영상 자체 조작은 막고 알람의 native 동작만 제공한다.

**Independent Test**: 유효 URL, 잘못된 URL, 네트워크 실패 상태에서 각각 예약과 임베디드 재생 결과를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 유효한 YouTube URL이 저장됨, **When** 정확 알람이 전달되고 세션 초기값 적용이 끝남, **Then** 별도 알림 탭 없이 앱 전체화면의 공식 임베디드 플레이어가 즉시 로드된다.
2. **Given** 네트워크 또는 자동 재생이 제한됨, **When** 플레이어가 로드됨, **Then** 오류 안내와 로컬 원형 해제 동선은 유지되며 YouTube 영상 표면에는 직접 조작 UI가 표시되지 않는다.
3. **Given** URL이 유효하지 않음, **When** 사용자가 알람을 저장함, **Then** 앱은 예약 전에 수정 가능한 오류를 표시한다.
4. **Given** YouTube 모드가 실행됨, **When** 콘텐츠가 재생됨, **Then** 루틴 알람은 콘텐츠를 다운로드·추출·광고 차단하거나 비공식 스트리밍하지 않는다.

---

### 사용자 스토리 7 - 권한 및 재시작 복구 (Priority: P5)

사용자는 필요한 시스템 접근의 상태와 이유를 이해하고, 기기 재부팅이나 접근 회수 후에도 알람 상태를 예측할 수 있다.

**Why this priority**: 모바일 OS 제약으로 인한 조용한 실패를 방지하고 실제 사용 신뢰를 높인다.

**Independent Test**: 각 접근을 하나씩 거부·허용·회수하고 재부팅하여 예약 가능 여부, 안내, 재등록 결과를 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 필수 접근이 없음, **When** 사용자가 예약을 시도함, **Then** 앱은 실패 이유와 해당 시스템 설정으로 가는 동선을 제공하고 성공으로 표시하지 않는다.
2. **Given** 미래의 활성 알람이 저장되어 있음, **When** 기기가 재부팅됨, **Then** 지원되는 정책에 따라 알람이 재등록되고 다음 실행 시각이 유지된다.
3. **Given** 예약 후 정확 알람 접근이 회수됨, **When** 사용자가 앱을 다시 확인함, **Then** 앱은 기존 예약의 보장 상태가 사라졌음을 표시하고 재승인을 안내한다.

---

### 사용자 스토리 8 - 로컬 알람과 최근 콘텐츠 관리 (Priority: P2)

사용자는 서버나 계정 없이 기기 안에서 여러 알람을 관리하고, 최근 사용한 알람 파일과 YouTube 주소를 다시 확인할 수 있다.

**Why this priority**: 개인용 로컬 서비스라는 제품 경계를 지키면서 자주 사용한 콘텐츠를 다시 찾기 쉽게 한다.

**Independent Test**: 로컬 파일과 YouTube URL을 사용한 알람을 저장한 뒤 앱과 기기를 재시작하여 최근 콘텐츠와 URL 복사가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 인터넷 연결과 계정이 없음, **When** 사용자가 알람을 저장함, **Then** 알람은 앱 전용 로컬 저장소에 보관되고 목록에 즉시 나타난다.
2. **Given** 로컬 파일 알람이 저장되거나 실행됨, **When** 사용자가 최근 콘텐츠 화면을 엶, **Then** 파일명과 이미지·영상 미리보기 또는 음악 미리듣기를 볼 수 있고 파일 주소 복사 기능은 없다.
3. **Given** YouTube 알람이 저장되거나 실행됨, **When** 사용자가 최근 콘텐츠 화면을 엶, **Then** URL을 확인하고 복사할 수 있다.
4. **Given** 같은 콘텐츠가 다시 사용됨, **When** 최근 콘텐츠가 갱신됨, **Then** 중복 행을 만들지 않고 최신 사용 시각으로 이동한다.
5. **Given** 사용자가 최근 목록 삭제를 누름, **When** 확인된 삭제가 완료됨, **Then** 최근 콘텐츠 목록만 지워지고 알람 정의와 원본 파일은 유지된다.

### Edge Cases

- 알람 수신과 사용자의 예약 취소가 거의 동시에 발생하는 경우
- 동일 알람 규칙이 요일과 포함 날짜에서 같은 날짜·시각을 동시에 선택하는 경우
- 스누즈 재울림과 다음 정규 발생 또는 다른 알람이 겹치는 경우
- 스누즈 대기 중 기기 시각·시간대 변경 또는 재부팅이 발생하는 경우
- 두 번의 시스템 전달 또는 서비스 재시작이 발생한 경우에도 초기 밝기·음량을 중복 적용하지 않는 경우
- 알람 시작 직전 또는 실행 중 앱 프로세스가 종료되는 경우
- 알람 중 기기가 재부팅되거나 배터리가 소진되는 경우
- 외부 디스플레이, 블루투스 오디오, 유선 이어폰이 연결된 경우
- 미디어 음량이 0이거나 방해 금지 모드가 활성화된 경우
- 자동 밝기가 활성화된 상태에서 시작 밝기를 적용하는 경우
- 선택한 문서 URI의 권한이 회수되거나 파일 형식이 실제 MIME 정보와 다른 경우
- YouTube URL이 단축 URL, 재생목록, Shorts, 라이브 스트림인 경우
- 기기 시각 또는 시간대가 예약 후 변경되는 경우
- 종료 X가 표시되기 전에 다른 앱으로 이동하려는 경우에도 전체화면 오버레이가 유지되는 경우
- 큰 글꼴, 화면 확대, TalkBack 상태에서 원형 종료 타이머와 남은 시간 안내를 사용할 수 있는 경우

## 요구사항

### 기능 요구사항

- **FR-001**: 시스템은 사용자가 미래의 알람 시각을 선택하고 저장할 수 있게 해야 한다.
- **FR-002**: 시스템은 복수 알람과 `ONE_TIME`, 선택 요일 `WEEKLY`, 모든 요일을 대상으로 하는 `DAILY`, 명시적 `INCLUDE_DATE`/`EXCLUDE_DATE` 예외를 지원해야 하며 제외 날짜를 우선하고 동일 날짜·시각의 중복 일치를 한 발생으로 처리해야 한다.
- **FR-003**: 시스템은 예약 전에 필수 접근 상태를 확인하고 부족한 접근을 구체적으로 알려야 한다.
- **FR-004**: 시스템은 예약 성공 여부와 각 알람의 다음 정규 실행 시각을 표시하고, 스누즈 중에는 정규 일정과 구분된 재울림 시각을 표시해야 한다.
- **FR-005**: 시스템은 지원 기기에서 잠금 상태의 알람을 사용자가 인지할 수 있는 전체화면 경험으로 제시해야 한다.
- **FR-006**: 시스템은 알람 시작 시 로컬 알람 생명주기를 시작하고 울림과 스누즈 대기 중 모두 사용 가능한 로컬 해제 경로를 유지해야 한다.
- **FR-007**: 사용자는 알람별 화면 잠금 타이머를 켜거나 끌 수 있어야 하며, 켜짐 상태의 지연을 0초부터 선택한 로컬 미디어 중 가장 긴 길이까지 설정할 수 있어야 한다. 로컬 길이를 확인할 수 없는 YouTube·기본 알람은 60초를 최대값으로 사용하며, 꺼짐 상태는 0초로 저장한다.
- **FR-008**: 화면 잠금 타이머가 켜져 있고 지연이 0보다 크면 시스템은 설정된 지연 동안 우측 상단 원형 진행률과 남은 시간을 표시하고 완료 전 종료를 허용해서는 안 된다. 타이머가 꺼져 있거나 지연이 0초면 알람 시작 즉시 종료·스누즈·위로 밀기를 허용한다.
- **FR-009**: 시스템은 정규 발생의 첫 울림 직전에 기존 밝기 값, 밝기 모드, 미디어 음량과 복원 정책을 세션당 한 번 영속 기록해야 한다.
- **FR-010**: 시스템은 알람 세션의 첫 울림에서 지정 밝기와 미디어 음량을 각각 한 번만 적용하고 스누즈 재울림에서는 재적용해서는 안 된다.
- **FR-011**: 시스템은 알람 실행 중 사용자의 밝기 조작을 감시하거나 되돌려서는 안 된다. `STREAM_MUSIC`은 사용자가 알람 목표보다 낮춘 경우에 한해 2초 간격으로 최대 음량의 5%(최소 1단계)씩 목표까지 올릴 수 있으며, 목표보다 높은 사용자 음량은 낮춰서는 안 된다. 이 감시는 FIRING 상태에서만 유지하고 스누즈 대기·종료·취소·선점 때 중지해야 한다.
- **FR-012**: 시스템은 [NEEDS CLARIFICATION: 자동 밝기 사용 중 초기 밝기를 확실히 적용하기 위해 수동 모드로 전환할지 정해지지 않음]에 따라 밝기 모드를 처리해야 한다.
- **FR-013**: 시스템은 `시작 전 값 복원` 정책에서 최종 해제 또는 실행 중 비활성화로 세션이 끝날 때 저장된 기기 상태를 한 번 복원하고 스누즈 진입 때는 복원해서는 안 된다.
- **FR-014**: 시스템은 `현재 값 유지` 정책에서 스누즈 진입과 최종 해제 시점의 기기 상태를 변경해서는 안 된다.
- **FR-015**: 사용자는 이미지, GIF 또는 영상 파일을 시각 콘텐츠로 선택할 수 있어야 한다.
- **FR-016**: 시스템은 선택한 파일의 읽기 접근을 앱 재시작 후에도 유지해야 한다.
- **FR-017**: 시스템은 별도 로컬 음악 파일 또는 영상 자체 오디오를 포그라운드 서비스에서 반복 재생하고 사용할 수 없을 때 기기 기본 알람음으로 대체해야 한다.
- **FR-018**: 시스템은 파일 접근 또는 렌더링 실패 시 기본 시각 화면으로 대체해야 한다.
- **FR-019**: 시스템은 선택한 영상 오디오 또는 로컬 음악을 읽거나 재생할 수 없을 때 기기 기본 알람음을 대체음으로 사용하고 오류를 로컬 기록에 남겨야 한다.
- **FR-020**: 시스템은 사용자가 홈으로 이동하거나 다른 앱을 열어도 로컬 음원을 계속 재생해야 한다.
- **FR-021**: 사용자는 YouTube URL을 저장 전에 검증받을 수 있어야 한다.
- **FR-022**: 시스템은 정확 알람 전달 뒤 초기 기기값 적용이 끝나면 별도 알림 탭 없이 공식 YouTube IFrame API 플레이어를 알람 전체화면 안에 표시해야 한다.
- **FR-023**: YouTube 임베디드 재생 중에도 시스템은 알람 세션·진행 알림·우측 상단 원형 해제 동선을 유지하고, 컨트롤·키보드·전체화면·터치·포인터 입력을 차단해야 하며 콘텐츠를 다운로드·추출·광고 차단해서는 안 된다.
- **FR-024**: 시스템은 재부팅 후 미래의 모든 활성 정규 발생과 진행 중인 미래 스누즈를 중복 없이 재등록해야 한다.
- **FR-025**: 시스템은 [NEEDS CLARIFICATION: 전원이 꺼진 사이 실행 시각이 지난 알람을 즉시 실행할지 건너뛸지 정해지지 않음]을 따라 만료 알람을 처리해야 한다.
- **FR-026**: 시스템은 정규 또는 스누즈 전달이 중복되어도 같은 발생·회차의 기기 상태 저장, 초기값 적용, 재생 시작을 한 번만 수행해야 한다.
- **FR-027**: 시스템은 울리기 전 취소, 반복 알람 비활성화, 현재 발생 최종 해제, 스누즈, 스누즈 중 비활성화를 서로 다른 상태 전이와 종료 원인으로 기록해야 한다.
- **FR-028**: 시스템은 YouTube 로드 실패와 파일 접근 실패를 사용자가 복구 가능한 방식으로 표시해야 한다.
- **FR-029**: 시스템은 계정, 원격 서버 또는 사용자 행동 분석 없이 핵심 로컬 알람을 제공해야 한다.
- **FR-030**: 시스템은 지원 범위 밖 기기나 OS에서 정확성을 보장하는 표현을 사용해서는 안 된다.
- **FR-031**: 시스템은 알람마다 안정적인 식별자와 활성 상태를 보관하고 각 알람의 시스템 예약을 독립적으로 생성·교체·취소해야 한다.
- **FR-032**: 시스템은 반복 알람의 다음 발생을 현지 날짜·시각 기준으로 계산하고, 활성화·복구 시 오늘의 유효 설정 시각이 남아 있으면 오늘을 우선하며, 기기 시각 또는 시간대 변경 시 다시 계산해야 한다.
- **FR-033**: 시스템은 제외 날짜를 포함 날짜와 기본 요일보다 우선 적용하고 같은 알람의 동일 발생을 한 번으로 중복 제거해야 한다.
- **FR-034**: 사용자는 한 정규 발생의 울림 및 각 스누즈 재울림에서 횟수 제한 없이 스누즈할 수 있어야 한다. 각 스누즈는 고유 회차와 5분 뒤 예정 시각을 가져야 한다.
- **FR-035**: 스누즈 기한은 사용자 동작 시점부터 고정 5분이어야 하며 시스템은 예약 성공과 재울림 시각을 표시해야 한다.
- **FR-036**: 스누즈는 현재 발생과 세션을 유지하며 원래 반복 규칙 또는 다음 정규 실행 시각을 변경해서는 안 된다.
- **FR-037**: 시스템은 스누즈 진입 시 재생과 전체화면 표시를 중지하되 대기 중 스누즈를 최종 해제할 로컬 경로를 유지해야 한다.
- **FR-038**: 시스템은 스누즈 재울림에서 기기 상태 스냅샷 저장과 초기값 적용을 반복해서는 안 된다.
- **FR-039**: 시스템은 동일 정규 또는 스누즈 동작과 시스템 전달을 멱등 처리해 예약과 재생을 중복 생성해서는 안 된다.
- **FR-040**: 실행 또는 스누즈 중 알람 정의 비활성화는 현재 세션, 대기 스누즈, 미래 정규 예약을 모두 종료하고 그 영향을 사용자에게 확인시켜야 한다.
- **FR-041**: 시스템은 알람 정의, 반복 규칙, 콘텐츠 설정, 다음 실행 시각을 앱 전용 로컬 데이터베이스에 저장해야 한다.
- **FR-042**: 시스템은 계정, 원격 API, 서버, 클라우드 동기화 또는 원격 분석 없이 알람 목록과 최근 콘텐츠를 제공해야 한다.
- **FR-043**: 시스템은 예약, 울림, 스누즈, 해제, 취소, 재등록, 오류 같은 행동 이벤트 로그를 저장해서는 안 된다.
- **FR-044**: 시스템은 최근 사용한 고유 로컬 파일 또는 YouTube URL을 최신순 30개까지 유지하고 사용자가 최근 목록만 전체 삭제할 수 있게 해야 한다.
- **FR-045**: 로컬 파일 최근 항목은 파일명과 열람·미리보기만 제공하고 파일 URI 복사 기능을 제공해서는 안 되며, YouTube 최근 항목은 URL 확인과 복사를 제공해야 한다.
- **FR-046**: GUI는 최소한 알람 목록, 알람 추가·편집, 최근 콘텐츠 화면과 필수 접근 상태를 제공해야 한다.
- **FR-047**: 다른 알람이 `CLAIMED`, `FIRING`, `SNOOZED` 또는 `SNOOZE_CLAIMED` 상태일 때 도착한 정규 발생은 기존 발생을 `PREEMPTED`로 종결하고 새 발생을 즉시 `CLAIMED`해 시작해야 한다. 두 알람을 동시에 재생하지 않으며 이전 정책의 `WAITING` 발생은 시작해서는 안 된다.
- **FR-048**: 새 정규 발생의 선점은 기존 스누즈 예약, 화면, 재생, 알람 알림을 정리하고 기존 복원 정책을 한 번 적용한 뒤 새 알람의 세션·기기 초기값을 시작해야 한다. 이미 재울림을 시작한 스누즈도 동일하게 선점한다.
- **FR-049**: 정규·스누즈 전달과 알림 액션은 `scheduleRevision`, `occurrenceId`, `sessionId`를 검증해야 하며, 스누즈 전달은 현재 `SNOOZED` 세션의 `snoozeCount`와 `dueAtMillis`까지 수신부와 재생 서비스에서 확인해야 한다. 같은 부팅에서는 elapsed realtime을 우선하고 조기 전달은 남은 기한으로 재예약하며, 전달 수락과 겹침 상태 결정은 로컬 데이터베이스 트랜잭션으로 한 번만 선점해야 한다.
- **FR-050**: 사용자는 알람의 시와 분 숫자 칸을 눌러 24시간 형식으로 직접 입력할 수 있어야 하며 범위를 벗어난 값을 저장할 수 없어야 한다.
- **FR-051**: 사용자는 테스트 예약 간격을 1~3600초 범위에서 직접 입력할 수 있어야 한다.
- **FR-052**: 시스템은 정확 알람을 Broadcast로 전달해 포그라운드 서비스를 먼저 시작하고, 화면이 켜지고 잠금 해제된 상태에서는 사용자가 허용한 다른 앱 위 전체화면 오버레이를 즉시 표시해야 한다.
- **FR-053**: 시스템은 화면이 꺼졌거나 잠긴 상태에서는 full-screen intent 알람 Activity로 화면을 켜고 잠금 화면 위에 표시해야 한다.
- **FR-054**: 시스템은 로컬 영상의 원본 방향을 감지해 화면 방향을 선택하고, 영상을 자르거나 늘이지 않은 채 원본 비율을 유지하면서 화면 안에 들어가는 최대 크기로 렌더링해야 한다.
- **FR-055**: 시스템은 영상의 90°/270° 회전 메타데이터까지 반영한 실제 표시 규격으로 가로·세로 방향을 결정하고 Activity와 화면 위 오버레이에 동일하게 적용해야 한다.
- **FR-056**: 사용자가 저장된 알람을 활성화할 때 날짜를 직접 선택하지 않았거나 이전 자동 계산으로 남은 `ONE_TIME` 날짜가 오늘보다 이전이면 오늘의 설정 시각이 아직 남았을 때 오늘로 예약하고, 이미 지났을 때만 내일로 보정해야 한다. `오늘`·`내일`·날짜 선택으로 지정한 미래 명시 날짜는 유지하되, 명시 날짜가 과거이거나 오늘의 시각이 지난 경우에만 오늘 우선 규칙에 따라 보정한다.
- **FR-057**: YouTube WebView는 설치된 앱 ID를 HTTPS Referer와 origin으로 제공해야 하며 임베드 금지, 삭제·비공개, 앱 식별 실패를 구분해 안내해야 한다.
- **FR-058**: 사용자가 로컬 시각 또는 음악 파일을 선택하면 시스템은 파일명을 표시하고 시각 파일은 실제 미리보기, 음악 파일은 미리듣기 동작을 제공해야 한다.
- **FR-059**: 로컬 알람 소리는 별도 음악 파일, 영상 자체 오디오, 기기 기본 알람음 순서로 자동 결정해야 하며 사용자가 내부 소리 소스 열거값을 버튼으로 선택하게 해서는 안 된다.
- **FR-060**: 원본 영상과 화면의 비율이 다를 때 시스템은 비율 차이로 불가피한 최소 여백만 가운데 배치하고, Activity와 화면 위 오버레이에서 동일한 맞춤 계산을 사용해야 한다.
- **FR-061**: 알람 재생 화면은 영상에 전체 화면 크기를 먼저 제공하고, 알람 이름·스누즈·종료 조작부는 영상 영역을 축소하는 고정 행을 차지하지 않고 비율 차이로 남는 여백 또는 영상 가장자리 위에 겹쳐 배치해야 한다.
- **FR-062**: 활성 울림 Activity는 뒤로가기로 닫히거나 알람을 종료해서는 안 되며, 홈·최근 앱 등으로 뒤로 밀리면 포그라운드 서비스가 활성 세션을 확인해 허용된 전체화면 오버레이를 즉시 복구해야 한다.
- **FR-063**: 종료 지연 중에는 전체화면 입력 차단막이 로컬 영상과 YouTube의 재생·일시정지·탐색·전체화면 조작을 막아야 하며, 종료 지연 완료 뒤에도 YouTube 영상 표면의 직접 조작은 계속 막고 현재 울림 회차의 native 스누즈·알람끄기만 사용할 수 있어야 한다.
- **FR-064**: 종료 지연 중과 완료 뒤 원형 진행 표시는 상태 표시 전용으로 해제 입력을 받지 않아야 하며, 지연 완료 뒤 입력 차단막을 제거하면서 하단 X와 위 스와이프만 활성화해야 한다.
- **FR-065**: Activity 이탈·화면 전환·화면 재점등은 활성 알람 세션의 최종 해제로 처리되어서는 안 되며, 최종 해제는 시간 검증을 통과한 현재 세션의 X 요청에서만 재생·알림·화면·기기 상태 복원을 함께 종료해야 한다.
- **FR-066**: 알람 Activity와 화면 위 오버레이는 표시 중 화면 켜짐을 유지해야 하며, 화면이 다시 켜지거나 잠금이 해제되면 포그라운드 서비스는 활성 세션에 맞는 Activity 또는 오버레이를 다시 표시해야 한다.
- **FR-067**: YouTube 일반 영상은 가로, Shorts URL은 세로를 초기 방향으로 사용하고 플레이어 준비 뒤에는 전체 방향 센서를 허용해야 한다.
- **FR-068**: 로컬 이미지·영상의 초기 방향은 회전 메타데이터가 반영된 실제 표시 비율로 결정해야 하며, 이후 센서 회전과 폴드 접기·펼치기·화면 크기 변경에서 재생 화면을 재생성하지 않고 다시 측정해야 한다.
- **FR-069**: 잠금화면 Activity와 다른 앱 위 오버레이는 동일한 재생 표면 생성 코드와 동일한 반투명 스누즈·원형 타이머·X·영상 배치 규칙을 사용해야 한다.
- **FR-070**: 화면 복구로 재생 표면 소유권이 바뀔 때 이전 표면은 마지막 재생 위치를 세션에 전달하고 중복 재생을 멈추며, 새 로컬 또는 YouTube 표면은 가능한 경우 전달받은 위치에서 이어 재생해야 한다.
- **FR-071**: 단순 화면 복구·방향 변경·폴드 크기 변경은 새 알람 시작으로 처리되어서는 안 되며 해제 타이머, 스누즈 횟수, 기기 상태 스냅샷과 초기값 적용 여부를 유지해야 한다.
- **FR-073**: 스누즈 예약 성공 뒤 재울림하는 로컬 영상과 YouTube는 같은 알람 세션의 이전 표면 위치를 이어받지 않고 0초부터 시작해야 하며, 스누즈가 아닌 화면 복구·방향 변경·표면 교체에서는 FR-070의 이어재생을 유지해야 한다.
- **FR-074**: 홈·편집 화면의 두 로컬 영상 미리보기는 각 카드의 고정된 출력 경계 안에서만 렌더링해야 하며, 중앙 크롭을 위해 카드 크기 자체를 확대해서는 안 된다.
- **FR-072**: 필수 접근 중 하나라도 준비되지 않으면 알람 추가·편집·테스트 진입을 차단하고 누락된 접근과 설정 버튼을 표시하되 기존 알람 목록과 최근 콘텐츠 열람·삭제는 허용해야 한다.
- **FR-073**: 앱은 권한 설정 또는 알림 권한 요청에서 돌아오는 즉시 필수 접근을 다시 계산하고, 편집 중 필수 접근이 회수되면 편집을 종료한 뒤 권한 안내 상태로 복귀해야 한다.
- **FR-074**: 로컬 콘텐츠 선택 화면은 이미지, GIF, WebP, 영상, 음악 탭을 제공하고 현재 탭에 맞는 지원 파일만 표시해야 한다.
- **FR-075**: 이미지·GIF·WebP·영상 탭은 기기 MediaStore의 시각 파일을 최신순 썸네일 격자로 표시하고, 음악 탭은 MediaStore.Audio의 파일명·길이·미리듣기 목록을 제공해야 한다.
- **FR-076**: 모든 미디어 탭은 최근순·이름순 정렬과 대소문자를 구분하지 않는 파일명 검색을 제공해야 하며, 지원하지 않는 MIME 형식과 비어 있거나 재생 길이를 확인할 수 없는 미디어는 목록에서 제외해야 한다.
- **FR-077**: 앱은 시각 콘텐츠용 Android 사진 선택기와 MediaStore에 없는 다운로드·클라우드 파일용 직접 찾아보기를 보조 경로로 유지하고, 어느 경로로 고르더라도 파일을 복사하지 않고 URI만 알람 정의에 저장해야 한다.
- **FR-078**: 기기 미디어 목록 권한은 파일 선택 기능에만 필요한 선택 접근이어야 하며, 사용자가 이를 거부해도 Android 사진 선택기와 직접 찾아보기 경로를 차단해서는 안 된다.
- **FR-079**: MediaStore의 MIME 정보가 비어 있거나 일반 형식이어도 파일명 확장자를 확인해 지원되는 미디어 탭의 목록으로 분류해야 하며, 지원하지 않는 확장자는 제외해야 한다.
- **FR-080**: 앱 최초 실행 시 필수 알람 접근 설정 화면을 먼저 표시하고, 모든 필수 접근이 준비되기 전에는 알람 추가·편집·테스트를 차단해야 한다. 사용자는 기존 알람과 최근 콘텐츠를 열람 전용으로 계속 볼 수 있어야 한다.
- **FR-081**: 새 `ONE_TIME` 알람은 오늘 날짜를 기본으로 사용해야 하며, 숫자 시·분 입력 중에는 중간 값 때문에 날짜를 변경하지 않아야 한다. 활성화 시 날짜 자동 보정은 FR-056의 오늘 우선 규칙을 따라야 한다.
- **FR-082**: 반복 방식 편집은 선택 요일 `WEEKLY`와 별도의 `DAILY`를 제공해야 한다. `DAILY`는 요일 선택 없이 매일 실행하고, 포함·제외 날짜를 적용하며 제외 날짜를 우선해야 한다.
- **FR-083**: 반복 알람을 현재 울림 화면에서 최종 해제하면 시스템은 해제한 날의 정규 발생을 다시 예약하지 않고 다음 유효 현지 날짜·시각을 저장·예약해야 한다. `DAILY`는 해제 후 내일부터 다시 울려야 하며, 일반 전달 직후 선행 예약이 누락된 경우에도 같은 규칙을 적용해야 한다.

### 주요 엔티티

- **Alarm**: 사용자가 정의한 예약. 안정적 식별자, 활성 상태, 현지 시각, 반복 규칙, 날짜 예외, 다음 정규 실행, 해제 지연, 복원 정책, 콘텐츠 설정을 가진다.
- **RepeatRule**: `ONE_TIME(localDate)`, `WEEKLY(daysOfWeek)` 또는 모든 요일을 의미하는 `DAILY` 중 하나와 공통 현지 시각을 가진다. `ONE_TIME`의 날짜는 사용자 선택 여부를 별도로 보관한다.
- **DateExceptions**: 유한한 `includeDates`와 `excludeDates` 집합. 제외가 우선하고 날짜별 다른 시각은 지원하지 않는다.
- **DevicePreset**: 알람 시작 시 한 번 적용할 밝기와 미디어 음량 시작값.
- **ContentProfile**: 로컬 시각 콘텐츠와 영상 자체 오디오·별도 로컬 음악·기기 기본 대체음 또는 YouTube 임베디드 설정 중 하나를 표현한다.
- **AlarmOccurrence**: `AlarmId + intendedLocalDateTime`으로 식별되는 정규 발생 건. 스누즈가 반복 규칙을 바꾸지 않게 분리한다.
- **AlarmSession**: 한 번의 정규 발생에서 최종 해제까지의 실행. 발생 식별자, 첫 시작 시각, 이전 기기 상태, 현재 단계, 스누즈 횟수·기한, 해제 원인, 복원 결과를 가진다.
- **PermissionStatus**: 정확 알람, 전체화면 알림, 알림 표시, 시스템 설정 변경 접근의 현재 가능 상태.
- **AlarmEvent**: 로컬에서 발생한 예약·울림·스누즈·해제·취소·복구·오류 기록. 알람 식별자, 시각, 종류, 짧은 결과만 보관한다.

### 상태 전이

```text
AlarmDefinition: DRAFT → SCHEDULED ↔ DISABLED → DELETED
                              ↘ PERMISSION_BLOCKED

AlarmOccurrence / AlarmSession:
PENDING → CLAIMED → FIRING_LOCKED → FIRING_DISMISSIBLE → DISMISSED
              ↘ PREEMPTED (새 정규 발생 우선)
              │                 │
              └── SNOOZE ───────┘
                      ↓
                  SNOOZED
                      ↓ +5분
                FIRING_LOCKED

PENDING → CANCELLED_BEFORE_FIRE
FIRING_* 또는 SNOOZED → CANCELLED_BY_DISABLE
CLAIMED/FIRING_*/SNOOZED → PREEMPTED
PENDING 또는 SNOOZED → EXPIRED
```

- `DISMISSED`는 복원 정책 적용 결과를 포함하는 종료 상태다.
- `CANCELLED`는 울리기 전에 사용자가 예약을 제거한 상태다.
- `PERMISSION_BLOCKED`는 저장된 의도는 있으나 OS 접근 부족으로 실행 보장이 없는 상태다.
- `EXPIRED` 처리 이후의 전이는 FR-025의 답변에 따라 확정한다.
- `SNOOZED`는 종료 상태가 아니며 같은 세션과 기기 상태 스냅샷을 유지한다.
- `WAITING`은 이전 FIFO 버전에서만 남을 수 있는 호환 상태이며 새 빌드에서는 취소하고 다시 시작하지 않는다.
- `PREEMPTED`는 현재 울림 또는 스누즈 세션이 새 정규 발생에 우선권을 넘기고 복원 정책까지 적용한 종료 상태다.

## 성공 기준

### 측정 가능한 결과

- **SC-001**: 지원 기기의 정상·잠금·절전 대기 조건에서 수행한 20회 테스트 중 최소 19회가 예약 시각으로부터 5초 이내에 알람 시작 신호를 발생시킨다.
- **SC-002**: 알람 시작 신호 후 2초 이내에 잠금 화면 full-screen intent 또는 잠금 해제 화면의 전체화면 오버레이가 사용자에게 표시된다.
- **SC-003**: 20회의 알람 실행에서 밝기와 미디어 음량 초기값은 세션당 각각 한 번만 앱에 의해 적용된다.
- **SC-004**: 실행 중 사용자가 밝기를 변경한 모든 검증 사례에서 앱은 해제 전 해당 값을 다시 덮어쓰지 않는다. 미디어 음량은 목표보다 낮아진 경우에만 2초 간격의 제한된 상승으로 복원하고, 목표보다 높은 값은 유지한다.
- **SC-005**: 두 복원 정책 각각 10회 테스트에서 해제 후 기기 상태가 선택한 정책과 100% 일치한다.
- **SC-006**: 로컬 알람은 홈 이동과 화면 잠금 후 최소 30분 동안 또는 사용자가 해제할 때까지 중 먼저 발생하는 시점까지 재생을 유지한다.
- **SC-007**: 이미지, GIF, 유음·무음 영상, 로컬 음악 각 3개 표본에서 앱 재시작 뒤 선택 콘텐츠와 소리가 재생되거나 명시된 기본 화면·알람음으로 2초 이내 대체된다.
- **SC-008**: 모든 YouTube 모드 네트워크 요청은 공식 임베디드 플레이어에만 사용되며 앱이 다운로드·추출한 미디어 파일을 생성하지 않는다.
- **SC-009**: 미래 알람이 있는 상태의 재부팅 테스트 10회에서 지원 정책에 맞는 예약 상태가 100% 복구된다.
- **SC-010**: 필수 접근이 거부된 모든 예약 시도에서 사용자는 두 번 이하의 화면 이동으로 해당 설정 화면 또는 제한 설명에 도달한다.
- **SC-011**: TalkBack과 200% 글꼴 크기에서 사용자는 알람 상태를 인지하고 지연 종료 후 해제 동작을 완료할 수 있다.
- **SC-012**: 경계일, 월말, 연말, 윤일, 시간대 변경을 포함한 최소 100개의 규칙 계산 사례에서 다음 실행과 포함·제외 우선순위가 기대 결과와 100% 일치한다.
- **SC-013**: 20회 스누즈 테스트에서 버튼을 누른 뒤 1초 이내 음원이 멈추고, 동작 시점부터 300초 후 허용 오차 5초 안에 재울림 시작 신호가 한 번 발생한다.
- **SC-014**: 스누즈를 포함한 20개 세션에서 기기 상태 스냅샷과 초기 밝기·음량 적용은 각각 세션당 한 번이고 최종 복원 또는 유지도 한 번이다. 새 알람 선점 시 이전 세션은 한 번 종결되고 새 세션의 목표 음량이 적용된다.
- **SC-015**: 최종 해제, 울리기 전 취소, 스누즈 중 비활성화 각각 10회에서 예약 잔존 여부와 종료 원인이 정의된 상태 전이와 100% 일치한다.
- **SC-016**: 동일 정규 또는 스누즈 전달을 두 번 주입한 각 20회 테스트에서 사용자에게 보이는 세션과 재생은 한 번만 시작된다.
- **SC-017**: 비행기 모드와 로그아웃 개념이 없는 상태에서 알람 생성·편집·삭제와 로컬 최근 파일 열람이 100% 동작한다.
- **SC-018**: 앱 재시작 10회 후 알람 목록과 최근 콘텐츠가 저장 직전 상태와 100% 일치한다.
- **SC-019**: 31개 이상의 서로 다른 콘텐츠를 사용한 뒤 최근 콘텐츠 수가 30개이고 같은 콘텐츠 재사용은 중복 행 없이 최상단으로 이동한다.

## 명시적 범위 제외

- YouTube 또는 다른 스트리밍 서비스의 미디어 다운로드, 캐시, 음원 추출, MP3 변환
- 사용자 계정, 클라우드 동기화, 원격 백엔드, 광고, 사용 분석
- 원격 로그 수집, 원격 오류 보고, 기기 간 알람 동기화
- 타인의 기기 원격 제어 또는 관리
- OS 보안 화면을 우회하는 잠금 해제
- 첫 정식 버전의 공휴일 캘린더, 위치 기반 알람, 날씨 기반 알람
- 월간·연간·격주·N일 간격 등 임의 반복 규칙과 사용자 설정형 스누즈 간격·횟수
- YouTube 자동 재생 성공, 영상 종료 감지, 광고 미표시 보장
- 제조사가 공식 Android 동작을 제한하는 모든 기기에 대한 무조건적 정확성 보장

## 가정

- 주 사용자는 자신의 Android 휴대전화 한 대에서 앱을 직접 설정하는 성인 사용자다.
- 핵심 시장 배포보다 개인 설치와 실제 Galaxy 기기 검증을 우선한다.
- 로컬 알람 기능은 인터넷 없이 동작해야 하며 YouTube 모드만 공식 임베디드 플레이어와 네트워크에 의존한다.
- 미디어 음량은 현재 Android 미디어 출력 경로를 사용하고 스피커 강제 전환은 기본 범위에 포함하지 않는다.
- 사용자는 특별 접근이 필요한 이유를 이해한 뒤 시스템 설정에서 직접 허용한다.
- 현재 스누즈는 한 정규 발생 안에서 횟수 제한 없이 사용할 수 있으며 간격은 5분으로 고정한다.
