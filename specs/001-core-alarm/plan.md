# 구현 계획: 복수 일정과 5분 스누즈

**Feature**: `001-core-alarm`  
**Date**: 2026-08-01  
**Scope of this plan**: 사용자가 확정한 D 일정 범위와 고정 5분 스누즈를 현재 단일 알람 프로토타입에서 신뢰 가능한 세로 슬라이스로 확장한다.

## 목표

규칙 계산과 한 번의 스누즈 상태 전이를 자동화로 증명한 뒤, Room 복수 저장소·Compose 목록/편집/기록 GUI와 알람별 정확 예약까지 세로로 연결한다. 실제 Galaxy 신뢰성 검증과 새 알람 우선 선점의 동시 전달 경계는 별도 게이트로 유지한다.

## 헌장 확인

| 원칙 | 계획 반영 |
|---|---|
| Alarm Reliability First | Android 반복 API에 의존하지 않고 다음 유효 발생 하나를 정확 알람으로 예약한 뒤 매번 다시 계산한다. |
| Initial Preset, Never Enforcement | 세션 첫 울림에서만 기기 상태를 저장·적용하고 스누즈 재울림에서는 반복하지 않는다. |
| Restore Is Explicit | 스누즈는 종료가 아니므로 복원하지 않고 최종 해제/실행 중 비활성화에서 한 번만 처리한다. |
| Local-First Media | 일정·스누즈는 네트워크와 독립적으로 동작한다. |
| External Content Is Handoff | YouTube 동작은 이번 일정 슬라이스와 분리한다. |
| Persistent State Is Recoverable | 알람 정의, 다음 발생, 활성 세션, 스누즈 기한을 프로세스 밖 저장소에 둔다. |

## 기술 방향

### 일정 계산

- 사용자 의도는 `LocalTime`, `ONE_TIME(LocalDate)`, 선택 요일 `WEEKLY(Set<DayOfWeek>)` 또는 모든 요일 `DAILY`, 포함/제외 `LocalDate`로 저장한다.
- 모든 규칙을 UTC 반복 주기로 환산하지 않는다. 현재 `ZoneId`에서 다음 유효 현지 날짜·시각을 계산한다.
- 제외 날짜가 최우선이고, 포함 날짜와 요일 규칙이 같은 후보를 만들면 하나로 합친다.
- 정확한 반복은 `setRepeating()` 대신 다음 발생 하나를 `setAlarmClock()`으로 등록하고 전달/시간대 변경/부팅 때 다시 계산한다.

### 저장소

- 현재 단일 `SharedPreferences` 레코드는 복수 알람과 세션 격리를 표현할 수 없어 교체한다.
- 계획상 영속 저장은 Room 기반으로 분리한다: `AlarmDefinition`, 날짜 예외, 현재 `AlarmSession`.
- 기존 단일 알람 데이터는 1회 마이그레이션하되 성공 전에 원본을 지우지 않는다.
- 데이터 계층은 Android 예약 API와 분리해 계산기와 상태 전이를 JVM 단위 테스트로 검증한다.

### 예약 식별

- 모든 예약/동작에 `alarmId`, `occurrenceId`, `scheduleRevision`, `sessionId`, `kind(REGULAR|SNOOZE)`를 전달한다. 스누즈 예약에는 `snoozeCount`와 `dueAtMillis`도 전달한다.
- 같은 `alarmId + occurrenceId + revision + kind`는 중복 수신되어도 한 번만 시작한다.
- 스누즈 수신부와 재생 서비스는 현재 `SNOOZED` 세션의 회차·예정 시각까지 이중 검증하고, 같은 부팅에서는 elapsed realtime을 우선한다. 조기 전달은 예약을 소모하지 않고 재등록한다.
- 알람별 PendingIntent와 알림 ID를 사용해 다른 알람을 잘못 취소하거나 해제하지 않게 한다.

### 겹침·기기 음량

- 단일 포그라운드 서비스·재생 세션을 유지하며, 새 정규 발생이 `CLAIMED`, `FIRING`, `SNOOZED`, `SNOOZE_CLAIMED` 활성 발생을 Room 트랜잭션에서 `PREEMPTED`로 선점한 뒤 즉시 시작한다.
- 이전 FIFO 구현에서 남은 `WAITING` 발생은 새 세션으로 승격하지 않고 취소한다. 서비스는 새 occurrence가 여전히 `CLAIMED`인지 확인한 뒤에만 이전 화면·재생·복원 상태를 정리해 오래된 start intent의 역선점을 막는다.
- 알람 세션의 시작 시 밝기·음량 초기값 적용은 한 번만 유지한다. 울림 중 `STREAM_MUSIC`이 알람 목표보다 낮아지면 2초마다 최대 음량의 5%(최소 1단계)씩 목표까지 올리고, 목표보다 높은 값은 건드리지 않는다. 스누즈 대기·선점·해제·취소·서비스 종료에는 감시 콜백을 취소한다.

### 스누즈

- 울림 및 각 재울림에서 스누즈할 수 있고 누른 시점부터 5분 뒤 정확 알람 하나를 예약한다. 스누즈 횟수에는 상한을 두지 않는다.
- 재생과 전체화면은 중단하지만 세션 스냅샷은 유지하고, 대기 알림에 재울림 시각과 최종 해제 경로를 둔다.
- 재울림에서 해제 지연은 다시 시작하되 스누즈는 제공하지 않는다.
- 원래 반복 일정은 스누즈와 독립적으로 계산·유지한다.
- 회차·예정 시각이 오래된 스누즈 전달은 Room 선점 전에 거부하고, 동일 회차의 중복 서비스 시작은 한 번만 재생한다.

## 단계

### Phase 0 — 명세 및 안전망

- D와 스누즈 수락 시나리오·상태 전이·성공 기준 확정.
- 기존 알림의 즉시 해제 액션이 해제 지연을 우회하는 문제 제거.
- 순수 반복 계산기와 스누즈 기한 계산 테스트 추가.

### Phase 1 — 현재 프로토타입 스누즈 세로 슬라이스

- 현재 단일 알람에 `FIRING → SNOOZED → FIRING → DISMISSED`를 연결한다.
- 5분 재울림을 영속 기록하고 부팅 후 미래 스누즈를 재등록한다.
- 스누즈 동안 기존 세션을 유지해 초기 밝기·음량 적용과 스냅샷 저장이 한 번인지 보장한다.
- 이 단계는 D 전체 완료가 아니라 스누즈 계약을 실행 가능한 코드로 검증하는 중간 단계다.

### Phase 2 — 복수 알람 저장·편집

- **구현 완료**: Room 스키마와 기존 단일 데이터 마이그레이션.
- **구현 완료**: 알람 목록/생성/편집/활성화/비활성화/삭제 UI.
- **구현 완료**: `ONE_TIME`, 선택 요일, 포함/제외 날짜 편집 및 다음 실행 미리보기.
- **구현 완료**: 실행 로그를 저장하지 않는 최근 콘텐츠 30개와 로컬 파일 열람·YouTube URL 복사·전체 삭제 UI.

### Phase 3 — 복수 정확 예약과 복구

- **구현 완료**: 각 활성 알람의 다음 정규 발생 하나를 독립 예약.
- **구현 완료**: 전달 후 다음 발생 갱신, 부팅/앱 업데이트/정확 알람 권한 복구.
- **구현 완료**: `TIME_SET`, `TIMEZONE_CHANGED`에서 미래 반복 재계산.
- **구현 완료 (0.15.20)**: 반복 알람 복구 시 저장된 미래 시각보다 현재 현지 날짜의 유효 시각을 우선하고, 울림 해제 시 오늘 회차를 건너뛰어 매일 알람을 내일부터 재예약한다.
- **구현 완료**: 알람별 알림/액션에 revision/occurrence/session 식별을 전달하고 Room 트랜잭션으로 정규·스누즈 전달을 원자적으로 선점한다.
- **구현 완료 (0.15.8)**: 현재 울림·스누즈 대기·스누즈 재울림 중 도착한 새 정규 발생은 Room에서 기존 occurrence를 `PREEMPTED`로 선점하고 새 알람을 즉시 시작한다. 이전 `WAITING` 행은 취소하며, 서비스의 `CLAIMED` 재검증으로 오래된 start intent의 역선점을 막는다.
- **구현 완료**: Activity 이탈과 화면 재점등을 세션 종료와 분리하고 서비스가 전체화면 표시를 복구하며, 종료 지연 동안 미디어 입력을 차단한다.
- **구현 완료**: 공통 네이티브 재생 표면, 센서·폴드 구성 변경 비재생성, 세션별 재생 위치 인계와 필수 권한 편집 게이트를 연결한다.
- **구현 완료 (0.12.0)**: 잠금화면 Activity와 `TYPE_APPLICATION_OVERLAY`에 공통 `AlarmOverlayController` UI를 적용하고, `HH:mm`/알람명·원형 타이머·잠금 손잡이·완료 후 X/160dp 위 스와이프/1회 스누즈를 연결한다.
- **구현 완료 (0.12.0)**: 타이머 전 미디어·종료·스와이프·스누즈 입력을 차단하고, X/스와이프와 스누즈를 기존 세션·서비스 시간 검증에 연결한다.
- **구현 완료 (0.12.0)**: 알람 편집 화면의 유효한 YouTube URL에 공식 썸네일·탭 재생·닫기 UI를 연결하고, 빈/지원 불가 주소 안내와 URL 변경 시 WebView 수명 정리를 추가한다.
- **구현 완료 (0.12.0)**: Galaxy 영상 조회를 Video·외부 Files 컬렉션으로 보조하고 size/IS_PENDING 필터와 필수 MIME 가정을 제거했으며, Android 14 선택 영상 권한과 조회 상태 안내를 연결한다.
- **구현 완료 (0.12.0)**: Android 14 선택 영상 전용 권한을 감지해 전체 목록 제한 안내와 전체 영상 접근 재요청 버튼을 제공하고 사진 선택기·직접 찾아보기 경로를 유지한다.

### Phase 4 — 현재 콘텐츠/기기 상태 기능 이관

- **구현 완료**: 로컬 이미지/GIF/영상과 영상 자체 오디오·별도 로컬 음악·기기 기본 대체음을 새 알람별 설정에 연결.
- **구현 완료**: 정확 알람 Broadcast에서 서비스와 전체화면 오버레이를 즉시 시작하고 YouTube 공식 임베디드 플레이어와 원형 X 해제 동선을 연결.
- **구현 완료 (0.15.8)**: 기기 `STREAM_MUSIC`이 알람 목표보다 낮아질 때만 2초 간격·최대 음량 5%(최소 1단계)로 목표까지 점진 복원하고, 선점·스누즈 대기·해제·취소·destroy에서 감시를 중단한다.
- **구현 완료 (0.15.9)**: 숫자 시·분 입력 중 날짜를 자동 변경하지 않고, 저장 시 오늘의 시각이 지난 경우에만 내일로 보정한다.
- **구현 완료 (0.15.10)**: 홈에서 선택한 다크·라이트 테마를 알람 추가·편집 화면까지 전달하고 편집 화면 루트에 현재 Material 배경을 적용한다.
- **구현 완료 (0.15.11)**: 알람 활성화 시 날짜 미지정 1회성 알람은 오늘 우선으로 계산하고, 직접 고른 날짜는 유지한다. 반복 편집에 요일별과 별도의 매일 규칙을 추가하고 Room 스키마 7에서 날짜 선택 표식을 보존한다.
- **구현 완료 (0.15.12)**: 홈 토글 활성화도 오래된 자동·과거 날짜를 오늘 우선으로 재기준하고 미래 명시 날짜는 보존한다. 레거시 날짜 표식을 미선택으로 이관하며 공통 울림 표면의 중앙 스와이프 영역을 명시적인 `알람끄기`·스누즈 버튼 아래에 배치해 버튼 터치 가로채기를 방지한다.
- **구현 완료 (0.15.13)**: 공통 울림 표면의 위로 밀기 영역을 하단 동작 행보다 위쪽으로 분리하고, `5분 스누즈`·`알람끄기`를 중앙 인접 가로 행으로 배치한다. 스누즈 후 종료 버튼만 중앙에 두며 화면 폭에 맞춰 행을 제한한다.
- **구현 완료 (0.15.15)**: 스누즈 예약에 회차·예정 시각을 함께 전달하고 Broadcast 수신부·재생 서비스에서 세션 identity와 due를 이중 검증한다. 같은 부팅은 elapsed realtime, 재부팅·미확인 부팅은 wall due를 사용하며 조기 전달은 남은 시간으로 재예약한다.
- **구현 완료 (0.15.16)**: `snoozeCount` 상한을 제거해 재울림마다 스누즈 버튼과 상태 전이를 유지하고, 스누즈 성공 시 별도 확인 알림을 발행하며 재울림 시작 때 정리한다.
- **구현 완료 (0.15.17)**: YouTube 공식 IFrame의 컨트롤·키보드·전체화면과 WebView 터치·포인터 입력을 차단해 영상은 표시 전용으로 유지하고 native 알람 동작만 허용한다.
- 자동 밝기는 수동 모드 전환으로 구현했으며 겹침 조정기를 연결했다. 만료 정책과 콘텐츠 실패 UX는 후속 결정·검증 대상으로 유지한다.

### Phase 5 — 증거 기반 검수

- lint, JVM 단위 테스트, 계측 테스트, APK 조립.
- 0.12.0 UI 정책 테스트는 시계 `HH:mm`, 타이머 잠금/완료, 160dp 위 스와이프 임계값, 짧거나 수평 드래그 거부, 1회 스누즈와 기존 세션 유지를 포함한다.
- YouTube 편집 미리보기 테스트는 빈/지원 불가/유효 URL 상태와 공식 썸네일 URL/HTML helper를 포함한다.
- MediaStore 영상 테스트는 Android 14 선택 권한, 조회된 행 수에 따른 0건/지원 불가 안내를 포함한다.
- 선택 영상 전용 권한 테스트는 직접 영상 권한과의 구분, 영상 제한 문구, 전체 접근 재요청 상태를 포함한다.
- Galaxy에서 잠금/Doze/재부팅/권한 회수/스누즈 전 과정을 기록.
- Reality Checker의 G0~G5를 통과하기 전에는 정식 완료로 표시하지 않는다.

## 현재 차단 결정

복수 알람 런타임을 Phase 3까지 완료하려면 다음 정책을 사용자와 고정해야 한다.

1. 전원이 꺼진 사이 지난 정규 알람과 지난 스누즈를 건너뛸지, 유예 시간 안에서 즉시 울릴지.
2. 파일 접근 상실과 손상 미디어에서 사용자에게 표시할 복구 안내 수준.

## 첫 구현 단위 완료 조건

- 규칙 계산 테스트가 요일, 포함, 제외, 중복, 월/연 경계를 통과한다.
- 스누즈 버튼은 울림과 모든 재울림에서 표시되며 횟수 제한 없이 동작한다.
- 스누즈 시 음원이 종료되고 정확히 5분 뒤 재울림 예약이 하나만 남는다.
- 스누즈 재울림은 기존 세션을 사용해 기기 초기값을 재적용하지 않는다.
- 알림에서 일반 해제가 설정 지연을 우회하지 않는다.
- `lintDebug`, `test`, `assembleDebug`가 성공한다.
